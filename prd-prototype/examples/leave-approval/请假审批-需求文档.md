## 1 概述

### 业务背景

公司约 300 人，请假目前靠微信报备加纸质单据，主管审批后由 HR 手工录入考勤表。问题有三个：员工不知道自己还剩几天假；主管经常漏批，审批记录散在聊天里；HR 月底要花 2 天核对请假天数。

本期把“发起 → 审批 → 余额扣减 → 月度统计”做成线上闭环。

### 建设目标

- 员工在手机上 1 分钟内完成一次请假申请，并随时看到剩余假期
- 主管在 PC 审批台集中处理待审批单据，不再漏批
- HR 每月直接查看按部门汇总的请假天数，不再手工核对

### 本期范围

| 端 | 模块 | 页面 |
| --- | --- | --- |
| 员工手机端 | 请假 | M01 请假首页、M02 发起请假、M03 请假详情 |
| 员工手机端 | 我的 | M04 我的 |
| 审批台（PC） | 审批 | P01 待我审批、P02 审批详情 |
| 审批台（PC） | 统计 | P03 请假统计 |

**明确不做**

- 加班、调休、出差申请（二期）
- 多级审批和会签：本期只有直属主管一级审批
- 与考勤机、薪资系统对接：HR 仍按月导出后手工处理
- 请假余额的年度发放规则配置：本期由 HR 线下维护后批量导入 【待确认】

### 角色与权限

| 角色 | 说明 | 权限 |
| --- | --- | --- |
| 员工 | 发起请假、查看自己的请假记录和余额 | 只能看到本人数据 |
| 直属主管 | 审批直属下属的请假 | 只能看到直属下属的单据；不能审批自己的请假 |
| HR | 查看全公司请假统计，不参与审批 | 可看全部部门；不能通过或驳回单据 |

## 3 核心流程

### 1. 员工发起请假

首页 → 填写申请 → 确认提交 → 查看详情 → 撤回

| 步骤 | 页面 · 状态 | 说明 |
| --- | --- | --- |
| 1 | M01 请假首页 · 有请假记录 | 首页能看到剩余年假 5 天。点“发起请假”。 |
| 2 | M02 发起请假 · 填写中 | 选择年假、开始和结束时间，时长自动算成 1.5 天。点“提交申请”。 |
| 3 | M02 发起请假 · 确认提交 | 确认弹层再次展示时长和余额变化。点“确认提交”。 |
| 4 | M03 请假详情 · 待审批 | 单据进入待审批，余额冻结 1.5 天。点“撤回申请”。 |
| 5 | M03 请假详情 · 撤回确认 | 撤回前二次确认。点“撤回”后余额解冻。 |

### 2. 主管审批

待审批列表 → 查看详情 → 驳回并填写原因

| 步骤 | 页面 · 状态 | 说明 |
| --- | --- | --- |
| 1 | P01 待我审批 · 有待审批 | 默认只显示待审批。点第一行的“审批”。 |
| 2 | P02 审批详情 · 查看详情 | 抽屉中看到申请人本年度请假记录，辅助判断。点“驳回”。 |
| 3 | P02 审批详情 · 填写驳回原因 | 驳回必须填写原因，员工会收到。点“确认驳回”。 |
| 4 | P01 待我审批 · 有待审批 | 处理完回到列表，该单据从“待审批”中消失。 |

## 4 全局规则

- 时长按**工作日**计算，以 0.5 天为最小单位；周末和法定节假日不计入（来源：澄清 Q2）
- 提交时先冻结余额，审批通过后正式扣减；驳回或撤回后解冻（来源：澄清 Q3）
- 假期余额按自然年计算，每年 1 月 1 日清零重发 【待确认】（来源：HR 口头说明，待书面确认）
- 单据状态：待审批 → 已通过 / 已驳回；待审批时员工可撤回 → 已撤回（来源：需求材料）

### 非功能要求

- 审批结果在 1 分钟内通过企业微信消息通知员工 【AI 假设】

## 5 页面需求

### 员工手机端

#### M01 请假首页 

- **页面目标**：员工打开即可看到各类假期的剩余天数和最近的请假记录，并从这里发起新的请假。
- **入口与前置**：企业微信工作台“请假”入口；首次进入自动用企业微信身份登录，无需输入账号
- **角色权限**：所有在职员工

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 有请假记录 | 本人至少有 1 条请假单（任意状态） |
| 无请假记录 | 新员工或本年度从未请过假 |

**功能点**

##### ① 假期余额 `balance`

展示年假、病假、事假三种假期的**可用天数**。点击某一种假期，带着该类型进入发起请假。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 可用天数 `left` | 数字（天） | 否 |  |  | 额度 − 已用 − 冻结中，保留 1 位小数 |
| 冻结中 `frozen` | 数字（天） | 否 |  |  | 大于 0 时在可用天数下方显示“另有 X 天审批中” |

**规则**

- 可用天数为 0 时数字显示为灰色，仍可点击，进入后该类型提示“余额不足”

<small>出现在：有请假记录、无请假记录 · 来源：需求材料 · 痛点 1</small>

##### ② 发起请假 `create`

主按钮，进入发起请假页，假期类型默认选中年假。

<small>出现在：有请假记录、无请假记录 · 来源：需求材料</small>

##### ③ 最近请假记录 `records`【AI 假设】

按提交时间倒序显示本人最近 5 条请假单，点击进入请假详情。超过 5 条时底部显示“查看全部”。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 假期类型 `type` | 枚举 | 否 |  | 年假、事假、病假 |  |
| 请假时间 `range` | 文本 | 否 |  |  | “11/05 上午 – 11/06 下午”格式，跨年时显示年份 |
| 时长 `days` | 数字（天） | 否 |  |  | 按工作日计算 |
| 状态 `status` | 枚举 | 否 |  | 待审批、已通过、已驳回、已撤回 | 待审批橙色、已通过绿色、已驳回红色、已撤回灰色 |

**规则**

- “查看全部”进入完整列表，列表页本期复用首页样式，不单独设计 【AI 假设】

**空数据**：显示“还没有请假记录”和“发起请假”按钮

<small>出现在：有请假记录、无请假记录</small>

#### M02 发起请假 

- **页面目标**：员工填写假期类型、起止时间和事由，系统自动计算时长并校验余额，提交后进入主管审批。
- **入口与前置**：首页“发起请假”按钮或点击某种假期余额卡片

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 填写中 | 进入页面，默认选中年假，开始时间为下一个工作日上午 |
| 校验未通过 | 点击“提交申请”时有必填项为空、时间不合法或余额不足 |
| 确认提交 | 校验通过后弹出确认层 |

**功能点**

##### ① 请假信息表单 `form`

依次选择假期类型、开始时间、结束时间，填写事由。开始和结束时间都选好后，系统**立即**按工作日计算时长并显示在“时长”一行。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 假期类型 `type` | 枚举 | 是 | 年假；从余额卡片进入时为对应类型 | 年假、事假、病假 | 余额为 0 的类型仍可选，选中后在下方提示“余额不足” |
| 开始时间 `start` | 日期 + 上午/下午 | 是 | 下一个工作日上午 |  | 可选过去 7 天内（补请假）到未来 90 天 |
| 结束时间 `end` | 日期 + 上午/下午 | 是 |  |  | 不早于开始时间；跨度不超过 30 个自然日 |
| 时长 `days` | 数字（天） | 否 |  |  | 只读，自动计算；结果为 0（如整段都在周末）时提示“所选时间都不是工作日” |
| 请假事由 `reason` | 文本 | 是 |  |  | 5–200 字，实时显示字数 |
| 证明材料 `proof` | 图片 | 否 |  |  | 病假超过 2 天时变为必填；最多 3 张，单张不超过 10 MB |

**规则**

- 切换假期类型时保留已填的时间和事由
- 离开页面时若已填写内容，弹出“放弃本次填写？”确认 【AI 假设】

<small>出现在：填写中、校验未通过 · 来源：需求材料 · 澄清 Q2</small>

##### ② 提交申请 `submit`

点击后先做前端校验：不通过时在对应字段下方显示红字原因，并滚动到第一个错误；通过后弹出确认层。

**规则**

- 余额不足时不允许提交：事假、病假不设余额上限 【待确认】

**异常与边界**

- 必填项为空：字段下方提示“请填写 xx”
- 时长超过可用余额：时长一行下方提示“年假可用 5 天，本次 6 天”

<small>出现在：填写中、校验未通过 · 来源：需求材料</small>

##### ③ 确认提交 `confirm`

底部弹层复述类型、时间、时长，并展示余额变化“可用 5 天 → 3.5 天（1.5 天冻结至审批完成）”。点“确认提交”后创建单据并进入请假详情。

**规则**

- 提交成功后通过企业微信通知直属主管
- 没有直属主管的员工（如总经理）提交后自动通过 【待确认】

**异常与边界**

- 重复点击只提交一次：按钮进入加载状态直到返回
- 提交时余额已被其他单据占用：关闭弹层，回到表单并提示最新余额
- 网络失败：弹层内提示“提交失败，请重试”，保留填写内容

<small>出现在：确认提交 · 来源：澄清 Q3</small>

#### M03 请假详情 

- **页面目标**：员工查看单据当前状态和审批进度；待审批时可以撤回。
- **入口与前置**：首页请假记录、提交成功后自动进入、企业微信审批结果通知

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 待审批 | 提交后、主管处理前 |
| 已通过 | 主管点击“通过”后 |
| 已驳回 | 主管填写原因并驳回后 |
| 撤回确认 | 待审批状态下点击“撤回申请” |

**功能点**

##### ① 单据信息 `info`

展示单号、假期类型、请假时间、时长、事由和证明材料。证明材料点击可全屏预览。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 单号 `no` | 文本 | 否 |  |  | 见数据字典“请假单.单号” |
| 时长 `days` | 数字（天） | 否 |  |  | 提交时计算并固定，之后节假日表变化不重算 【AI 假设】 |

<small>出现在：待审批、已通过、已驳回 · 来源：需求材料</small>

##### ② 审批进度 `progress`

时间线展示“提交 → 主管审批”两个节点，每个节点显示处理人和时间；驳回时显示驳回原因。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 审批人 `approver` | 文本 | 否 |  |  | 提交时的直属主管；主管变更后，待审批单据**不**自动转给新主管 【待确认】 |
| 驳回原因 `reason` | 文本 | 否 |  |  | 仅已驳回时显示，原文展示主管填写内容 |

<small>出现在：待审批、已通过、已驳回 · 来源：需求材料</small>

##### ③ 撤回申请 `withdraw`

仅**待审批**状态显示。点击后弹出确认框，确认后单据变为“已撤回”，冻结的余额立即退回。

**规则**

- 已通过的单据不能撤回，需要销假时线下找 HR 处理（本期不做销假）

**异常与边界**

- 主管已在此期间处理：提示“单据已被审批，无法撤回”，并刷新为最新状态
- 网络失败：提示“撤回失败，请重试”，单据状态不变

<small>出现在：待审批、撤回确认 · 来源：澄清 Q3</small>

##### ④ 重新发起 `again`【AI 假设】

已驳回时显示，进入发起请假并**带入原单据的类型、时间和事由**，员工修改后作为新单据提交。

<small>出现在：已驳回</small>

#### M04 我的 

- **页面目标**：员工核对自己的部门和直属主管，确认请假会发给谁审批。
- **入口与前置**：底部导航“我的”

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 默认 | 任何员工进入 |

**功能点**

##### ① 个人信息 `profile`

只读展示姓名、部门、直属主管，数据来自企业微信通讯录，每天凌晨同步一次。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 部门 `dept` | 文本 | 否 |  |  | 企业微信通讯录的主部门 |
| 直属主管 `leader` | 文本 | 否 |  |  | 为空时显示“未设置，请联系 HR”，此时提交的请假自动通过 【待确认】 |

**规则**

- 信息有误时引导员工联系 HR 修改通讯录，本系统不提供修改入口

<small>来源：需求材料 · 角色说明</small>

### 审批台（PC）

#### P01 待我审批 

- **页面目标**：主管集中查看并处理直属下属的请假单，优先处理开始时间最近的单据，避免漏批。
- **入口与前置**：审批台默认首页；企业微信“有新的请假待审批”消息直接打开对应单据的审批详情
- **角色权限**：直属主管；HR 账号不显示此菜单

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 有待审批 | 直属下属至少有 1 条待审批单据 |
| 全部处理完 | 筛选“待审批”且没有单据 |

**功能点**

##### ① 状态筛选与搜索 `filter`

按状态切换列表，默认“待审批”；搜索框按申请人姓名或单号模糊匹配，输入后 300 毫秒自动查询。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 状态 `status` | 枚举 | 否 | 待审批 | 待审批、已处理、全部 | “已处理”包含已通过和已驳回；已撤回的单据不出现在主管列表 【AI 假设】 |
| 搜索关键词 `kw` | 文本 | 否 |  |  | 匹配申请人姓名或单号，不区分大小写，最多 30 字 |

<small>出现在：有待审批、全部处理完 · 来源：需求材料 · 痛点 2</small>

##### ② 请假单列表 `table`

每页 20 条，“待审批”按开始时间**升序**（最紧急在前），其他状态按提交时间倒序。点“审批”或整行打开审批详情抽屉。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 申请人 `applicant` | 文本 | 否 |  |  | 姓名 + 部门 |
| 类型 `type` | 枚举 | 否 |  | 年假、事假、病假 |  |
| 请假时间 `range` | 文本 | 否 |  |  | 开始时间距今 ≤ 1 天时标红“明天开始” |
| 时长 `days` | 数字（天） | 否 |  |  | 按工作日计算 |
| 提交时间 `submitted` | 时间 | 否 |  |  | 24 小时内显示“x 小时前”，否则显示日期 |
| 状态 `status` | 枚举 | 否 |  | 待审批、已通过、已驳回 |  |

**规则**

- 只显示直属下属的单据；主管本人的请假不会出现在自己的列表中

**空数据**：显示“没有待审批的请假”，并提供“查看已处理”链接

<small>出现在：有待审批、全部处理完 · 来源：需求材料</small>

#### P02 审批详情 

- **页面目标**：主管在不离开列表的情况下查看单据和申请人本年度请假情况，做出通过或驳回。
- **入口与前置**：待我审批列表的“审批”按钮；企业微信消息直达
- **角色权限**：该单据申请人的直属主管

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 查看详情 | 打开一条待审批单据 |
| 填写驳回原因 | 点击“驳回” |

**功能点**

##### ① 申请信息 `summary`

展示申请人、部门、假期类型、请假时间、时长、事由和证明材料。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 时长 `days` | 数字（天） | 否 |  |  | 同员工端，提交时固定 |
| 证明材料 `proof` | 图片 | 否 |  |  | 点击放大预览；病假超过 2 天必有 |

<small>出现在：查看详情 · 来源：需求材料</small>

##### ② 申请人本年度请假 `history`【AI 假设】

列出申请人本年度已通过的请假汇总（按类型合计天数）和年假剩余，帮助主管判断是否批准。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 已请天数 `sum` | 数字（天） | 否 |  |  | 本自然年内已通过的单据合计，按类型分别统计 |
| 年假剩余 `left` | 数字（天） | 否 |  |  | 扣除本单冻结后的可用天数 |

<small>出现在：查看详情</small>

##### ③ 通过 / 驳回 `decide`

“通过”直接生效并扣减余额；“驳回”弹出原因填写框。处理后抽屉关闭，列表中该单据移出“待审批”。

**规则**

- 单据开始时间已过仍可审批，通过后按原时间计入考勤
- 主管不能修改单据内容，只能通过或驳回

**异常与边界**

- 员工已撤回：提示“申请人已撤回此单据”，刷新列表
- 已被处理（如在手机端处理过）：提示“该单据已处理”，显示处理结果
- 网络失败：提示“操作失败，请重试”，抽屉保持打开

<small>出现在：查看详情 · 来源：需求材料 · 澄清 Q1</small>

##### ④ 驳回原因 `reject-form`

驳回必须填写原因，原因会随通知发给员工。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 驳回原因 `reason` | 文本 | 是 |  |  | 2–100 字；提供 3 个常用原因快捷填入：“时间冲突，请调整”“请补充证明材料”“请先与我当面沟通” |

**异常与边界**

- 原因为空时“确认驳回”按钮不可点
- 提交失败时保留已填原因并提示重试

<small>出现在：填写驳回原因 · 来源：需求材料</small>

#### P03 请假统计 

- **页面目标**：HR 每月按部门查看请假天数，导出后用于考勤核算，替代手工核对。
- **入口与前置**：顶部导航“请假统计”
- **角色权限**：HR；主管账号不显示此菜单

**页面状态**

| 状态 | 出现条件 |
| --- | --- |
| 按月查看 | 默认显示上个自然月 |

**功能点**

##### ① 统计月份 `month-pick`

选择要统计的自然月，切换后表格和合计同时刷新。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 月份 `month` | 年月 | 是 | 上个自然月 |  | 可选范围：系统上线月份至本月 |

<small>来源：需求材料 · 痛点 3</small>

##### ② 部门请假汇总 `dept-table`

按部门汇总当月**已通过**的请假天数；跨月的请假按落在当月的工作日拆分计入。

| 字段 | 类型 | 必填 | 默认值 | 可选值 | 规则与口径 |
| --- | --- | --- | --- | --- | --- |
| 部门 `dept` | 文本 | 否 |  |  | 企业微信通讯录一级部门 |
| 请假人数 `people` | 数字 | 否 |  |  | 当月有已通过请假的去重人数 |
| 年假 `annual` | 数字（天） | 否 |  |  | 当月已通过的年假天数合计 |
| 病假 `sick` | 数字（天） | 否 |  |  | 同上 |
| 事假 `personal` | 数字（天） | 否 |  |  | 同上 |

**规则**

- 待审批、已驳回、已撤回的单据不计入统计

**空数据**：当月没有已通过的请假时显示“本月没有请假记录”

<small>来源：需求材料 · 澄清 Q4</small>

##### ③ 导出明细 `export`【AI 假设】

导出当月所有已通过单据的明细（每张单据一行），文件名“请假明细-2026年10月.xlsx”。

**规则**

- 导出范围与当前月份一致，不受页面分页影响

**异常与边界**

- 超过 5000 行时改为后台生成，完成后通过企业微信发送下载链接 【AI 假设】

## 7 数据字典

| 字段 | 类型 | 说明 |
| --- | --- | --- |
