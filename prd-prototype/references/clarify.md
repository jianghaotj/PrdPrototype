# 轻量澄清与范围清单

目标：用最少的问题，堵住 AI 自由发挥的口子。只问会改变页面、功能点或业务规则的**决策**；能从材料里查到的**事实**自己查。

## 1. 先整理已知事实

把材料（PRD、会议纪要、截图、几句话描述、已有原型）整理成下面 6 个维度。每个维度标“清楚 / 缺失 / 有歧义”。

| 维度 | 缺失时 AI 会怎么自由发挥 |
| --- | --- |
| 本期边界（做什么、不做什么） | 加上看起来合理但没人要的模块 |
| 用户与角色、权限差异 | 臆造角色和权限矩阵 |
| 核心流程（从哪开始、到哪结束） | 多画页面、多画分支 |
| 端与设备（PC、手机、小程序） | 端的分工乱配 |
| 关键规则与口径（计算、状态流转、校验） | 编造计算方式和状态机 |
| 核心数据对象 | 字段随手写 |

全部清楚：跳过提问，直接出范围清单。

## 2. 提问规则

- **最多 2 轮，每轮不超过 6 题。** 第 2 轮只问第 1 轮答案引出的新问题。
- **原型阶段（`product.stage: 'prototype'`）最多 1 轮，可以跳过。** 只问决定页面、状态和功能点的问题。规则、口径、字段不问。
- **每题给推荐答案**，措辞让用户回“是”就等于采纳推荐。用户可以回“全部按推荐”或“1 是，3 改成……”。
- **按影响排序**：边界 > 角色 > 流程 > 端 > 规则 > 数据。
- **一题一个决策点**。同一个决策下紧密相关的细节（如“按工作日算、最小 0.5 天”）可以放在同一个推荐答案里；彼此独立的决策分开问。依赖其他题答案的问题放到下一轮。
- **不问视觉细节**：只确认出线框还是高保真（写进范围清单）。高保真的配色、字体、组件样式由你按 `references/hifi.md` 自行设计，不追问；用户主动给了品牌色、设计稿或截图时照用。文案，以及能自己查到的事实、对页面和规则没有影响的细节，也不问。
- 2 轮后仍没定的，按推荐写入，标 `[AI 假设]`，在范围清单里列出，不再追问。

格式：

```
❓ **Q1 · 审批层级**：请假审批是一级（直属主管）还是多级（主管 → HR）？
➡ 推荐：本期一级。多级审批会多出流转配置和撤回规则，可放二期。

❓ **Q2 · 时长口径**：请假时长按自然日还是工作日计算？
➡ 推荐：按工作日，最小单位 0.5 天（周末和法定节假日不计入）。
```

## 3. 范围清单（必须等用户确认）

确认后，先建项目（`SKILL.md` 流程 A 第 4 步），再按清单写出 `prd/scope.json`（范围基线），然后才写页面代码。模板：

```
**范围清单 · 产品名 V1.0**

端：员工手机端（企业微信 H5）、审批台（PC）
视觉：线框（要高保真时写“高保真，视觉由 AI 自拟”）
公共组件（外壳导航，建项目时自动生成）：PC 顶部导航 pc-shell/pc-nav；手机底部导航 m-shell/m-tab

| 页面（ID 与名称） | 状态（ID：名称） | 功能点（ID：名称） | 依据 |
| --- | --- | --- | --- |
| M01 请假首页 | list：有记录；empty：无记录 | balance：假期余额；create：发起请假；records：最近记录 | 材料 §1 |
| M02 发起请假 | form：填写；err：校验失败；confirm：确认提交 | form：请假信息表单；submit：提交申请；confirm：确认提交 | 材料 §2、Q2 |
| P01 待我审批 | list：有待审批；empty：全部处理完 | filter：状态筛选与搜索；table：请假单列表 | 材料 §3 |

ID 与最终原型的页面、状态、功能点 ID 一致；用户确认后，就按这里的 ID 写入 `prd/scope.json`（格式见 `spec-format.md` 文末）。

核心流程：员工发起请假；主管审批
本期不做：多级审批、加班调休、考勤机对接
AI 假设（会在原型和文档中标出）：首页显示最近 5 条记录；驳回后可“重新发起”并带入原内容
待确认（不影响先出原型）：余额是否按自然年清零

回复“确认”开始制作；需要增删页面或功能点请直接说。
```

清单里的每个功能点都必须能在依据列找到来源，或者明确列在“AI 假设”里。

原型阶段（`stage: 'prototype'`）的清单只列页面、状态、功能点的编号和名称，依据列可以省略。本期不做、AI 假设、待确认照常列出。

已有 HTML 原型时，清单再加两块：

```
公共组件：侧边导航、顶栏（原型中每页都有）
原型中有、不纳入本次需求（写进 end.ignore）：导出 Excel（本期不做）、发布向导入口（评审范围外）
需求中有、原型未体现（写成 gap）：顶栏“使用帮助”入口
```

## 4. 记录

- 每个问答写进 `product.clarify`：`{ no: 'Q2', q: '…', a: '…', by: '用户确认' | '采纳推荐' | 'AI 假设' }`。
- 采纳推荐得到的结论，对应功能点 `src` 写“澄清 Q2”；用户只回了“全部按推荐”时，`by` 写“采纳推荐”，汇报时提醒用户这些是推荐值。
- 范围清单之外的内容（用户后来补充的）同样写 `src`，如“11/05 用户补充”。
- 范围确认后，写需求时发现的细节（规则口径、校验、异常处理）不必再停下来问：按常见做法写，标 `[AI 假设]` 或 `status: 'assumed'`，在交付汇报里列出最重要的几条请用户确认。会增删页面或功能点的变化，按 `SKILL.md` 硬性规则“范围确认”处理，不必停下来另起一轮确认。
