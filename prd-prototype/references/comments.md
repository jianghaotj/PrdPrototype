# 评审意见回收

评审的人在交付 HTML 里对功能点留意见，导出 JSON；修改需求的人用 `scripts/merge-comments.mjs` 把几份 JSON 合并，再按流程 C 改源文件。

## 评审的人怎么用

- **功能点卡片**：每张功能点卡片标题右侧有“意见 (N)”按钮，点开是该功能点的浮层，可以看到已有意见、写新意见。
- **顶栏“意见”**：打开右侧抽屉。可以切换“本页”和“全部”，选中某个圆点（按 `N` 显示圆点）后，新意见会挂到那个功能点；不选则挂到本页。抽屉底部“导出意见 JSON”下载文件。
- 原型阶段和托管模式都能用。原型阶段的抽屉不占用右侧需求栏，需求栏本来就没有。

意见保存在评审的人自己的浏览器里（`localStorage`，键名 `prd-comments:<产品 ID>`），不上传，也不影响交付文件。换浏览器或清除站点数据会丢失，导出 JSON 即可备份。作者名单独记在本机；导出时文件顶层带上作者，条目里作者为空的也会用这次导出的作者补上。

每条意见记下提出时的版本（`release`）。升版后旧意见仍在，导出时全部带上；抽屉里不是本版提出的意见会标出原版本。1.2.3 之前留下的意见没有版本记录，标“版本未知”，不按当前版本补猜。

## 挂在哪里（target）

| 对象 | target 写法 | 例子 |
| --- | --- | --- |
| 功能点 | `页面ID/功能点ID` | `P02/decide` |
| 公共组件功能点 | `S:端ID/功能点ID` | `S:pc/pc-nav` |
| 页面级 | `页面ID` | `P01` |

页面功能点 ID 与 `scope.json` 的写法一致（`页面ID/功能点ID`）。公共组件在意见里是 `S:端ID/功能点ID`，在 `scope.json` 里是 `公共/组ID/功能点ID`，两边不一样。改名或删除功能点后，旧意见不会自动迁移。

## 导出 JSON

```json
{
  "v": 1,
  "productId": "leave-approval",
  "productName": "请假审批",
  "release": "V1.0",
  "exportedAt": "2026-11-05T02:00:00.000Z",
  "author": "张三",
  "comments": [
    {
      "id": "c_mw33j7el7xxm81",
      "target": "P02/decide",
      "pageId": "P02",
      "fnId": "decide",
      "release": "V1.0",
      "text": "驳回时要填写原因",
      "author": "张三",
      "at": "2026-11-05T01:00:00.000Z",
      "resolved": false
    }
  ]
}
```

顶层 `release` 是导出时的版本，条目里的 `release` 是提出时的版本；旧条目没有这个字段。文件名为 `<产品名>-评审意见-<导出时版本>-<日期>.json`。`resolved` 目前恒为 `false`，界面里还没有“已处理”操作。

## 合并

```bash
node scripts/merge-comments.mjs 张三.json 李四.json -o 评审意见合并.md --prd <项目目录>
```

- 同一条意见出现在多份文件里只算一次（按 `id` 去重）。
- 产品不同，或导出时的版本（顶层 `release`）不同时报错，不合并。
- 先按提出时的版本分组，再按对象分组。导出时的版本是“本轮”，排最前，是这次要处理的；其他版本是“历史意见”，没有版本记录的是“版本未知”，都排在后面。后两类先确认在本版是否仍适用，不直接当作本版要求。
- `--prd` 可选。给了项目目录，会按构建同样顺序读 `product.js`、`kit.js`、根目录其他 JS 和 `pages/**`，标题里带上功能点名称（含公共组件）；读不到时只写 target，合并本身不受影响。
- 序号按输出顺序全文连续编号，流程 C 用 `src: '评审意见 #3（张三）'` 引用。条目作者空时先用该文件顶层 `author`，仍空才写“未署名”。

输出示例：

```markdown
# 评审意见合并 · 请假审批 · V1.1

共 3 条意见，来自 2 份文件。序号按本文件顺序编号。
“本轮”是这次要处理的意见；历史意见和版本未知的意见，先确认在 V1.1 里是否仍适用，不直接当作本版要求。

## V1.1（本轮）

### P02/decide · 通过 / 驳回
- #1（张三，2026-12-02）：驳回时要填写原因
- #2（李四，2026-12-02）：同意主管看到病假详情需要二次确认

## V1.0（历史意见）

### P01 · 待我审批
- #3（王五，2026-11-05）：列表默认按提交时间排序？
```
