# 高保真：由模型自己设计视觉

技能不内置任何公司或团队的设计规范。用户要高保真时，视觉方案由你（模型）按产品和用户来定，写进项目的 `prd/theme.css`，需要新组件或改组件尺寸时再写 `prd/theme-kit.js`。需求、对账检查和线框完全一样，高保真只换样式层。

完整用例见 `examples/course-mgmt/prd/`：`theme.css` 是自拟的深青色教务后台风格，`theme-kit.js` 加了弹窗四档宽度、缺省页和分页。

## 什么时候出高保真

- 范围清单里写明“线框”还是“高保真”，用户确认后再定。用户说“要高保真”“要像真的一样”“给领导看效果”时选高保真。
- 新建时加 `--hifi`：`new.mjs` 生成 `prd/theme.css` 骨架，PC 端默认 1440×900，`fidelity` 写“高保真（视觉由 AI 自拟）”。已有线框项目改高保真，自己新建 `prd/theme.css`，把 `fidelity` 改掉即可。
- 托管模式（已有 HTML）沿用原 HTML 的样式，不出高保真。
- 用户给了自己的设计稿、截图或品牌色，以用户给的为准，来源写进 `theme.css` 文件头；没给的部分仍由你补，并在文件头标 `[AI 假设]`。

## 先定方向，再写变量

动手前先用两三句话写下视觉方向，放在 `theme.css` 文件头的注释里。方向从需求材料里来：

- **谁在用、用多久**：天天用的后台要克制、信息密度高；面向学生或消费者的端可以更鲜明、留白多。
- **行业气质**：教育、金融、医疗、政务、零售的常见色调和语气不同。挑一个主色并说明理由，不要每个项目都用同一种蓝。
- **品牌线索**：材料里出现的产品名、Logo 描述、已有截图里的颜色，优先沿用。

再定下面这些，写成 CSS 变量（变量名沿用 `wire.css`：`--ink --ink2 --ink3 --line --line2 --fill --fill2 --pg --acc --accw --ok --okw --warn --warnw --err --errw --r --r-lg --font`，项目需要时可以再加）：

| 项目 | 要求 |
| --- | --- |
| 配色 | 一个主色加浅底，三级文字色，两级分割线，两级填充，页面底色，成功、警告、错误各一对（深字 + 浅底）。正文和说明文字在背景上的对比度不低于 4.5:1，主按钮文字不低于 4.5:1 |
| 字体与字阶 | 用系统字体栈（`wire.css` 的 `--font` 已包含苹方、微软雅黑）。字阶 5–6 档，例如 12 / 13 / 14 / 16 / 20 / 24；标题 600，正文 400；行高 1.5–1.7 |
| 间距 | 4 的倍数。页面内边距、卡片内边距、表单项间距各定一个值，全项目统一 |
| 圆角与阴影 | 控件一档、卡片和弹窗一档；阴影最多两档（卡片、浮层） |
| 尺寸 | 按钮、输入框、表格行的高度各定一档，弹窗和表格内可以再小一档 |

## 组件状态都要画

高保真和线框的主要差别在状态。每类组件至少覆盖：

- **按钮**：默认、悬停、按下、键盘焦点（`:focus-visible` 外圈）、禁用、提交中（`h.submit` 自带“提交中…”）。
- **输入框**：默认、悬停、聚焦、出错（`.inp.bad`，配合 `.ferr` 提示）、禁用、占位文字。
- **列表和表格**：表头、行悬停、选中、空数据（`h.empty`）、搜索无结果（`h.rows` 自带）。
- **弹层**：遮罩、弹窗头体脚、抽屉；Toast。
- **选中态**：页签、胶囊、单选、复选、开关、步骤条、导航当前项，统一用主色。

## 让画面像真的

- 演示数据写成真实感的内容：真实格式的编号、日期、金额、人名和机构名，长短不一，包含一两条边界数据（很长的名称、0、空值）。数据是演示用的，不当作需求依据；涉及业务口径的仍按规则标 `[AI 假设]`。
- 图标用 `h.i` 的内联 SVG。头像、封面图用色块或首字，不引用网络图片。
- 不引用网络字体、CDN 样式或图片：断网检查会报 `HOST_NET` 或 `RES`，交付物也就不是单文件了。

## 写法约束

- 选择器都以 `.ab` 开头，只改画板，不改评审外壳（目录、需求面板、顶栏）。只给 PC 画板用 `.ab[data-device="pc"]`，只给手机画板用 `.ab[data-device="mobile"]`。
- 页面代码不写色值。需要新的样式就在 `theme.css` 里加语义类名（如样例的 `.lst-h`、`.lst-r`），页面只写类名。内联样式只用于宽度、字号和字距这类布局细节。
- 组件扩展写在 `prd/theme-kit.js`（任意 `prd/` 根目录下的 `.js` 都会在 `kit.js` 之后、`pages/` 之前加载）。只改 PC 端时用 `W.device === 'pc'` 判断，手机端调用原实现，参考样例。
- 页面里新增的可点元素照样要挂 `data-fn`；高保真不放宽任何检查。

## 自查

写完一条代表流程（例如列表 → 新建 → 提交 → 列表更新）后先截图看一眼，确认方向再写其余页面：

```bash
node scripts/snap.mjs <产物.html> --view "#/p/P01/create"
```

逐项看：

- 主色只用在主按钮、当前项、链接和关键数字上，没有铺满整页。
- 文字层级一眼能分出标题、正文、说明。
- 同类组件尺寸一致，间距对齐。
- 悬停、焦点、出错、禁用、空数据的样子都看过（用 `--view` 打开对应状态）。
- 圆点没有压住文字（用功能点的 `dot` 调整）。

汇报时说明“视觉方案由 AI 自拟，没有对齐公司设计规范”，并列出主色和字阶，请用户确认方向。
