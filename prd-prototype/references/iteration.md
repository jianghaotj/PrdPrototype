# 版本迭代与本版变化

用于“基于上一版做 V1.1”“只看本期变化”。原则：不重写旧需求，变化记在发生变化的条目上，让研发一眼看到这一期改了什么。

## 步骤

1. **追加版本。** 在 `product.releases` 末尾加一项，最后一项就是当前版本：

   ```js
   releases: [
     { id: 'V1.0', date: '2026-11-03', summary: '首版' },
     { id: 'V1.1', date: '2026-12-01', summary: '审批支持转交；统计增加按人查看' }
   ]
   ```

2. **按本期材料做轻量澄清和范围清单**（`clarify.md`），清单只列本期新增、修改、移除的页面和功能点。
3. **在条目上记录变化。** 页面、功能点、字段、规则条目都可以带 `changes`：

   ```js
   { id: 'transfer', name: '转交审批', desc: '……', src: 'V1.1 需求 §2',
     changes: [{ ver: 'V1.1', type: 'added' }] }

   { id: 'decide', name: '通过 / 驳回', desc: '（改成新的内容）', src: '……',
     changes: [{ ver: 'V1.1', type: 'modified', note: '通过后增加“同步到考勤”选项' }] }

   { id: 'history', name: '申请人本年度请假', desc: '……',
     changes: [{ ver: 'V1.1', type: 'removed', note: '评审决定去掉，避免主管看到病假详情' }] }
   ```

   - `added`：本版新增。
   - `modified`：本版修改，必须写 `note`（改了什么、为什么），条目内容直接改成新内容。
   - `removed`：本版移除，必须写 `note`；**条目保留在数据里**用于追溯，但必须从原型 render 中删掉。
   - 同一条目跨多个版本变化时，`changes` 里按版本追加多项。
   - 新增页面只需在页面上写 `added`，页面里的功能点自动视为本版新增；修改页面时则在具体的功能点、字段、规则上标记。
   - 本版新增又在本版删除的条目，直接删掉，不记录。
   - 未变化的条目不加 `changes`，不要把旧内容全部标成本版修改。

   可以带 `changes` 的对象：页面、页面状态、功能点、字段、页面规则、功能点的 `rules` / `errors` 条目、公共组件功能点；产品级的 `goals`、`scope.out`、`rules`、`nfr` 条目，`roles`、`dict`（及其字段）、`flows`、对象形式的 `todo`。

   澄清问题的编号接着上一版继续编（V1.0 到 Q6，V1.1 从 Q7 开始），回答写进同一个 `clarify` 数组。

4. **改原型。** 新增的功能点画出来并绑定，修改的按新需求调整，移除的从 render 中删掉。
5. **构建。** 检测到版本号变化时，上一版交付文件会自动复制到 `<项目>/归档/<文件名>-V1.0.html`。增删按 `SKILL.md` 硬性规则“范围确认”处理：先普通构建，核对实际增删都在本版已确认范围内，再加 `--scope-baseline` 刷新 `prd/scope.json`，不再问一遍。这样本版确认的内容不再算“范围确认后新增”。
6. **汇报**：本版新增、修改、移除各几项，以及归档文件路径。同时看基线差异和本版 `changes`：用 `removed` 标记移除的条目不报 `SCOPE_REMOVED`，这部分移除数从 `changes` 统计，直接删除的看基线差异。

## 阅读端

存在多个版本时：

- 顶栏出现“本版变化”开关。打开后画板只显示本版有变化的功能点圆点（绿色新增、紫色修改），右侧面板展开变化项、折叠未变化项，并显示已移除项（红色删除线）。
- 左侧目录用彩色圆点标出有变化的页面。
- 需求文档工具栏有“只看 V1.1 变化”：先列产品级变化（目标、范围、角色、全局规则全文、数据字典、流程），再列有变化的页面和条目；“变更记录”一章列出每个版本的变化明细。
- 截图验证：`node scripts/snap.mjs <产物.html> --chg --view "#/p/M04"`。
- 导出 Markdown 时，开关打开就只导出本版变化。

版本切换只筛选需求记录，原型画面始终是当前版本。需要回看旧画面时打开 `归档/` 里的旧文件。

## 检查

- `changes.ver` 必须是 `releases` 中登记的版本。
- `modified` 和 `removed` 必须写 `note`。
- 标记为 `removed` 的功能点如果还出现在原型里，构建失败。
