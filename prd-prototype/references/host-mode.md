# 为已有 HTML 补需求（托管模式）

适用：用户已有一个 HTML 原型（AI 生成、手写或导出），可能还有一份照着原型写的 PRD，要合成一份能拿去评审的原型需求。原型画面保持原样，需求、页面目录、圆点标注、需求文档由本技能提供。

原型放在 sandbox iframe 中运行：样式和脚本与外壳互不影响；原型不能跳转整个评审页；原型的本地 CSS、JS、图片在构建时内联。

## 事实依据

- **有 PRD**：PRD 是需求依据，`src` 引用它的章节；原型是界面依据。
- **只有原型**：原型画出来的界面是事实，规则、口径、权限这些原型看不出来的内容要问。
- **两者冲突**（原型和 PRD 不一致、PRD 自相矛盾）：写成澄清问题，推荐一个答案；没问到的标 `[待确认]`。
- 不要因为原型里有某个按钮就认定它是需求：PRD 里找不到依据的，作为澄清问题或 AI 假设处理。

## 流程

1. **复制材料，不改原文件。** 原文件只读。缺失的本地资源（如引用了不存在的 logo）只会产生提醒，不阻止构建；确需补资源时，把原型复制到 `prd/host/`，在副本旁放资源，`host` 指向副本，并在汇报中说明。
2. **建项目。** `node scripts/new.mjs <项目目录> --name "产品名" --id 英文短名 --host <原型.html>`。
3. **探测结构。** `node scripts/probe-host.mjs <原型.html>`，它在与构建相同的 iframe 环境中运行，输出：
   - 需要留意的风险：iframe 自检测、跳转顶层窗口、原生对话框、本地存储、依赖当前时间、网络请求；
   - 可在进入步骤中调用的全局函数（如 `showPage`、`navTo`）；
   - 页面、弹层、浮层、空状态容器，以及当前是否可见（用于 `match`）；
   - 当前可见的可交互元素和建议选择器（用于 `sel`），重复元素已合并。
   用 `--steps` 先进入某个页面或弹层再探测，`--boot` 模拟 `end.boot`，`--shot` 截图确认。
4. **整理事实，轻量澄清**（`clarify.md`）。重点问：原型和 PRD 不一致的地方、原型里有但 PRD 没写的功能本期做不做。
5. **出范围清单并确认。** 额外列出公共组件、“原型中有、不纳入本次需求”、“需求中有、原型未体现”。
6. **写页面需求。** 每个原型页面一个 `W.page`，没有 `render`；用 `enter` 到达、`match` 识别、`sel` 绑定。
7. **构建修到通过。** 原型中所有可见的可交互元素都必须归属到功能点，或写进 `end.ignore`。
8. **截图检查**（`snap.mjs`），汇报（同 SKILL.md）。

## 配置

```js
ends: [{
  id: 'web', name: '管理后台', device: 'pc', home: 'D01',
  host: '../原型/crm.html',          // 相对 prd/ 的路径
  // online: true,                    // 可选：原型确需联网（引用 CDN 脚本或样式）时显式放行，交付标“需联网”
  width: 1440, height: 900,           // 原型的设计尺寸
  ignore: [                           // 原型里有、不纳入本次需求的元素
    { sel: '#btn-export', name: '导出 Excel 按钮', why: '原型多出的功能，本期不做' },
    { sel: '.entry-card', name: '发布向导入口', why: '向导另行评审', label: '评审范围外' },
    { sel: '#task-table a.op-link', text: '查看', name: '行操作“查看”', why: '任务详情页另行评审', label: '评审范围外' }
  ],
  boot: [{ js: "document.body.classList.remove('in-iframe')" }],   // 可选：每次加载原型后先执行
  settle: 150,                              // 可选：进入步骤执行完后的等待毫秒数
  resetKeys: ['crm-']                       // 可选：“重置演示数据”时清除的 localStorage 前缀
}]
```

`ignore` 每一项：

| 字段 | 说明 |
| --- | --- |
| `sel` | 必填，CSS 选择器；元素及其内部的可交互元素都不再要求登记 |
| `why` | 必填，为什么不纳入 |
| `name` | 建议填，可读名称，进入需求文档 |
| `text` | 可选，只匹配文字包含该内容的元素（同一选择器匹配多种按钮时用） |
| `label` | 可选，原型上和需求文档里显示的标签，默认“本期不做”；不在本次评审范围的写“评审范围外” |

原型上，被 ignore 的元素用红色虚线框出并显示标签（小元素只显示 ✕，悬停看原因），每条规则最多标 3 处。需求文档“需求与原型的差异”一章按标签分组列出。

```js
W.page({
  id: 'C01', end: 'web', group: '客户', title: '客户列表',
  goal: '……',
  match: '#page-customers',                       // 页面可见时成立
  enter: [{ js: "showPage('customers')" }],       // 从原型初始画面到达本页
  states: [
    { id: 'list', label: '列表', when: '……' },
    { id: 'new', label: '新建客户', when: '点击“新建客户”', layer: 'modal',
      enter: [{ click: '#btn-new' }], match: '#modal-new' }    // 在页面 enter 之后继续执行
  ],
  fns: [
    { id: 'filter', name: '搜索与筛选', sel: '#kw, #level', desc: '……', fields: [……], src: 'PRD §3.1' },
    { id: 'table', name: '客户表格', sel: '#customer-table', desc: '……', fields: [……], empty: '……', src: 'PRD §3.2' },
    { id: 'form', name: '新建客户表单', sel: '#modal-new .modal', desc: '……', fields: [……], errors: [……], src: 'PRD §3.3' },
    { id: 'import', name: '批量导入', desc: '……', src: 'PRD §3.4', gap: '原型未画出导入入口，以需求为准' }
  ]
});
```

### 进入步骤 enter

每次切换到某个状态，原型都会重新加载，执行 `end.boot`，然后依次执行 `page.enter` 和 `state.enter`：

| 步骤 | 说明 |
| --- | --- |
| `{ js: "showPage('x')" }` | 在原型里执行脚本，可调用原型的全局函数 |
| `{ click: '#btn', text: '新建' }` | 点击元素；`text` 可选，选择器匹配多个时按文字筛选 |
| `{ hover: '.tabs-hint' }` | 悬停（触发 mouseover / mouseenter 并聚焦），用于只靠悬停出现的浮层 |
| `{ hash: '#/orders' }` | 修改原型地址的 hash |
| `{ input: '#kw', value: '北京' }` | 输入内容并触发 input / change |
| `{ waitFor: '.result', timeout: 3000 }` | 等待元素出现 |
| `{ wait: 300 }` | 等待毫秒数 |

每步可加 `after: 毫秒` 控制步后等待。

### 识别 match

评审者在原型里点来点去时，右侧需求会自动切到匹配的页面状态。

- 字符串：可见元素的选择器，如 `'#page-customers'`、`'.modal.show'`。
- 对象：`{ sel, text, hash, js }`，全部满足才成立。`js` 是返回布尔值的表达式。
- 弹层状态（写了 `layer`）优先于页面状态；状态没写 `match` 时继承页面的 `match`（弹层状态除外）。
- 弹层状态只显示和检查 `match` 所匹配元素内部的功能点。浮层长在触发元素里面时，若希望触发元素的功能点也显示，`match` 写成 `{ sel: '触发元素', js: '浮层可见的判断' }`，不写 `layer`。
- 所有状态都匹配不上时，画板下方显示“当前画面未在需求中登记”，这通常说明原型里有需求没覆盖的画面。

### 绑定 sel

- `sel` 是 CSS 选择器，可以是选择器列表（`'#kw, #level'`）。元素归属到**最近的**匹配祖先所属的功能点。
- `text` 可选：只匹配文字包含该内容的元素。
- 选一个能把同一功能的元素都包住的容器，但不要绑到 `body` 或整个页面容器上。
- 原型缺少稳定选择器时，可以在 `prd/host/` 的副本上只添加 `data-fn="功能点ID"` 属性（不改视觉、不改交互），说明原因。

### 需求有、原型没有：gap

PRD 里有、已有原型没画的功能（或原型画法与需求不同），在功能点上写 `gap`：

```js
{ id: 'top-entries', name: '顶栏快捷入口', desc: 'U校园数据、使用帮助、我的消息三个入口……', src: 'PRD §2.2',
  gap: '原型顶栏只有页面标题和头像，缺少这三个入口，以需求为准' }
```

写了 `gap` 的功能点不要求 `sel`，也不会因原型里找不到而报错；右侧面板和需求文档标“原型未体现”，并在“需求与原型的差异”一章列出。只在已有 HTML 上使用；原生线框原型应直接画出来。

## 检查与展示

- 构建时按每个状态进入原型，检查当前可见的可交互元素（含 `cursor: pointer` 的自定义点击区域）：没有归属功能点、也不在 `ignore` 里的，构建失败。
- 功能点的 `sel` 在任何状态都看不到，构建失败（写了 `gap` 的除外）。
- `enter` 执行失败或执行后 `match` 不成立，构建失败。
- 检查时原生 `alert / confirm / prompt` 会被自动确认并给出提醒，不会卡住。
- 原型引用的图片、字体缺失或在网络上，只给提醒（断网时可能显示异常）。
- 原型引用的网络脚本或样式（`<script src="https://…">`、`<link rel="stylesheet" href="https://…">`）会阻止交付（`HOST_NET`）：构建在断网环境下运行，这类资源加载不了，原型会失效。确需联网的端，在 `ends` 里写 `online: true`，构建改为 `ONLINE` 提醒，交付说明里标“需联网”。

## 原型阶段

在 `product.js` 写 `stage: 'prototype'`，托管项目交付 `<产品名>-原型.html`，打开直接进第一个端的首页。

- `sel` 绑定和 `ignore`（含 `why`）仍要写。原型阶段只放宽需求说明类的提醒；`HOST_SEL`、`HOST`、`UNREGISTERED`、`FN_UNUSED` 照常报错。
- 虚线框（`ignore` 标出的元素）和编号圆点一起默认隐藏。按 `N` 一起显示，再按一起隐藏。打开页面时回到隐藏，显示状态不保存。
- 该端写 `online: true` 时，顶部标为“原型阶段 · 检查通过 · 需联网”。
- 不能用 `--md` 导出需求文档，构建会直接报错。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 原型检测到自己在 iframe 里，隐藏了侧边栏或顶栏（`self !== top`） | 在 `end.boot` 里撤销它的改动，如 `{ js: "document.body.classList.remove('in-iframe')" }` |
| 原型点击后跳转 `window.top` / `parent`（如跨页面菜单） | sandbox 会拦下，点击无反应。属于需求范围的，改由目录或 `enter` 进入对应页面；不在范围的写进 `ignore` |
| 删除、撤回等用原生 `confirm` 二次确认 | 原生对话框无法标注，把确认文案和规则写进触发它的功能点 `rules` / `errors` |
| 只靠悬停出现的浮层 | `enter` 用 `{ hover: '选择器' }` |
| 进入步骤报“找不到要点击的元素” | 用 `probe-host.mjs --steps` 复现前几步，看元素是否已出现；必要时加 `{ waitFor }` |
| 原型初始化慢、动画多 | 调大 `settle`，或在 enter 末尾加 `{ wait: 300 }` |
| 原型把状态存在 localStorage | 用 `boot` 在加载时清理，或配置 `resetKeys` |
| 演示数据按当前日期计算，日期过了就看不到某些标签 | 写进需求的待确认或 `demoNote`，不要改原型 |
| 点击原型后右侧没切换 | 检查对应状态的 `match` 是否在该画面可见 |
| 大量“不属于任何功能点” | 先判断是不是真需求：是就登记功能点；不是就写进 `ignore` 并写原因；装饰性的 `cursor: pointer` 也放进 `ignore` |
| 功能点“在任何状态都没出现” | 依次排查：`sel` 是否写对（probe 核对）；元素是否被原型在 iframe 中隐藏（用 boot）；原型确实没画（写 `gap`） |
